# Security Notes (CR-4)

این سند تصمیم‌های امنیتی اعمال‌شده برای یافته **CR-4** (کلیدهای API و اطلاعات شخصی بدون حفاظت) و محدودیت‌های باقی‌مانده‌ی این نسخه را توضیح می‌دهد.

## ۱. کلیدهای ووکامرس دیگر ذخیره/منتشر نمی‌شوند

**مشکل:** در نسخه‌های قبلی، `consumerKey`/`consumerSecret`:

- به‌صورت ثابت در سورس‌کد (`src/data.ts`) commit شده بود،
- پس از ورود کاربر به‌صورت **متن ساده** در `localStorage` نوشته می‌شد،
- و تست اتصال مستقیماً از مرورگر با آن‌ها درخواست می‌زد.

**اقدامات اعمال‌شده:**

| # | اقدام | محل |
|---|---|---|
| 1 | حذف کامل کلیدهای واقعی از seed؛ مقدار پیش‌فرض خالی + `isConnected: false` | `src/data.ts` |
| 2 | **Session-only credentials**: تابع `stripWooCredentials()` پیش از هر نوشتن در `localStorage` و پیش از ساخت فایل پشتیبان، کلیدها را از state حذف می‌کند | `src/store.tsx` |
| 3 | **مایگریشن پاک‌سازی**: اگر نسخه قدیمی کلیدهایی را در `localStorage` جا گذاشته باشد، هنگام بار state خالی می‌شوند (یک‌بار و idempotent) | `migrateLegacyData` در `src/data.ts` |
| 4 | فیلدهای فرم Woo با `autoComplete="off"` / `"new-password"` و `spellCheck={false}` تا کلید وارد autofill/املای مرورگر نشود؛ متن راهنما و toast صادقانه درباره عمر نشست‌محور کلید | `src/Woo.tsx` |
| 5 | بنر هشدار در صفحه Woo: «اگر کلیدی هرگز ذخیره شده، آن را Revoke کنید» | `src/Woo.tsx` |
| 6 | تایپ `WooSettings.consumerKey/consumerSecret` اختیاری شد تا نبودشان در داده‌های ماندگار مدل‌سازی شود | `src/types.ts` |

**⚠️ اقدام فوری بیرون از کد:** کلیدهای `ck_7b99…` / `cs_8fa4…` که در تاریخچه git (کامیت اولیه `98c2df3`) وجود دارند **لو رفته محسوب می‌شوند**. حتی با حذف از HEAD، در تاریخچه باقی‌اند؛ بنابراین باید در پیشخوان WooCommerce → Settings → Advanced → REST API **Revoke** و کلید جدید ساخته شود. اگر مخزن public بوده، history-rewrite (`git filter-repo`) هم توصیه می‌شود — اما جایگزین باطل‌کردن کلید نیست.

## ۲. معماری درست برای محیط عملیاتی: پروکسی سمت سرور

کلیدهای Woo باید **هرگز** به مرورگر نرسند. الگوی پشتیبانی‌شده در این بیلد:

```
Browser ──► GET <VITE_WOO_PROXY_BASE or proxyBaseUrl>?url=<encoded woo endpoint>
                 │
        Backend proxy (Node/PHP/nginx)
                 │  کلیدها فقط اینجا: env / secret manager
                 ▼
            WooCommerce REST API
```

- آدرس پروکسی را در تنظیمات صفحه Woo یا متغیر محیطی `VITE_WOO_PROXY_BASE` قرار دهید.
- در این حالت می‌توان فیلدهای کلید را در UI کاملاً پنهان کرد؛ هیچ کلیدی در باندل JS یا مرورگر نمی‌ماند.
- نمونه پروکسی (Express):

```js
app.get('/api/woo-proxy', verifyAdminSession, async (req, res) => {
  const u = new URL(req.query.url);
  u.searchParams.set('consumer_key', process.env.WOO_CONSUMER_KEY);
  u.searchParams.set('consumer_secret', process.env.WOO_CONSUMER_SECRET);
  const r = await fetch(u);
  res.status(r.status).json(await r.json());
});
```

## ۳. هویت ثابت کاربر حذف شد

نام ساختگی «سارا محمدی / مدیر ارشد سامانه» در هدر (`src/App.tsx`) به **«کاربر محلی / بدون احراز هویت»** تغییر کرد تا کاربر را درباره وجود لاگین گمراه نکند و PII ساختگی در UI نباشد.

## ۴. محدودیت شناخته‌شده: داده‌های دانش‌آموزان در localStorage

این پروژه یک اپ **صرفاً کلاینت** است؛ کد ملی، شماره تماس و مشخصات دانش‌آموزان (اکثراً زیر ۱۸ سال) در `localStorage` همان مرورگر نگهداری می‌شود. رمزنگاری سمت کلاینت راه‌حل واقعی نیست (کلید رمز هم در همان مرورگر است). برای بهره‌برداری واقعی الزامی است:

1. **بک‌اند + پایگاه‌داده** (state فعلی JSON-سازگار است و قابل مهاجرت).
2. **احراز هویت** و **RBAC** (مدیر / کارشناس ثبت‌نام / مالی) — حداقل سطح دسترسی خواندن PII محدود به نقش شود.
3. **لاگ ممیزی** (audit log) برای افزودن/ویرایش/حذف و پرداخت‌ها.
4. انتقال `localStorage` به **کوکی HttpOnly + SameSite** برای session و حذف داده حساس از کلاینت.
5. انطباق با قانون حفاظت از داده کودکان/حریم خصوصی (اجازه ولی، کمینه‌سازی داده، حق حذف).

تا پیش از اجرای موارد بالا، این نسخه فقط برای **محیط توسعه/دموی محلی** مناسب است و نباید روی دستگاه مشترک یا عمومی داده واقعی دانش‌آموزان در آن ثبت شود.
